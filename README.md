# Derian Córdoba · Portfolio

A static, content-first portfolio built with Astro, TypeScript, and Tailwind CSS. Includes English and Spanish homepages, three professional case studies and three open-source project pages in each language, localized CV downloads, and an accessible gateway simulation.

## Run locally

Use Node.js 24.16+, 26.3+, or 22.23.4+. The engine range covers Astro and the lint toolchain.

```sh
npm ci
npm run dev
```

Open `http://127.0.0.1:4321`. Build with `npm run build`; deploy the generated `dist/` directory to a static host. `npm run preview` serves the production output locally.

## Architecture

This project uses an MVVM-inspired presentation layer without adding a reactive application framework. Pure view models prepare page data; Astro components render it. The gateway demo has a small DOM controller that binds a pure state model to the view.

```text
src/
  domain/                 Framework-independent contracts
  application/ports/      Content repository interface
  infrastructure/         Astro content adapter and composition root
  presentation/
    view-models/          Pure page and interaction data transformations
    controllers/          Progressive DOM bindings
  content/                Typed profile data and Markdown case studies
  components/             Small UI, section, visual, and layout components
  layouts/                Shared document and case-study layouts
  pages/                  Static route composition and metadata endpoints
```

See [architecture decisions](docs/architecture.md) for dependency rules and tradeoffs.

## Edit content

- Update identity and contact details in `src/content/profile.ts`. Update bilingual career roles, summaries, and canonical employment dates in `src/content/career.json`; date labels are generated by `src/content/career-period.ts`.
- Add or edit case studies in `src/content/studies/en/` and `src/content/studies/es/`. The collection schema validates metadata during the build. Keep the same `studyId` in each translated pair and set the corresponding `locale`.
- Use `kind: experience` for `/work/{id}/` or `kind: project` for `/projects/{id}/`.
- Prepare and translate CVs manually, then replace `public/Derian-Cordoba-CV-2026.pdf` and `public/Derian-Cordoba-CV-2026-ES.pdf`. CV translation and PDF generation are not automated by this project.
- Change `SITE_URL` when moving to a custom domain, then rebuild. It controls canonical URLs and the sitemap.
- Change design tokens in `src/styles/global.css`; reusable UI components live in `src/components/ui/`.

Professional summaries and the All-Win leadership case study are grounded in the supplied CV. Open-source descriptions are grounded in repository documentation. Diagrams and the circuit-state interaction are illustrative. The separate gateway replay uses captured local HTTP responses and a complete text transcript; it is not production telemetry.

## Localization

English keeps the original URLs (`/`, `/work/.../`, `/projects/.../`). Spanish uses `/es/` with the same stable page slugs. The header's EN/ES links preserve the current page; JavaScript also preserves query parameters and the current fragment. Native links work without JavaScript.

UI strings are in `src/i18n/en.ts` and `src/i18n/es.ts`. Spanish dictionaries must satisfy the English key contract. Shared routing helpers own locale detection, links, and CV selection. Career translations share each company record in `src/content/career.json`. Both locale-specific content and the gateway view model use the same presentation components.

Document language, canonical and alternate language URLs, Open Graph metadata, social images, accessibility labels, error pages, diagrams, and downloadable CVs are localized. `/404.html` is the static host's default English error document; `/es/404/` is the translated error page. Configuring a host to use the Spanish document for unknown `/es/*` paths is a hosting concern.

## Page transitions

Every page uses Astro's `ClientRouter` through `BaseLayout`, including homepages, case studies, engineering notes, hiring overviews, confirmation pages, and error pages. Page content fades and rises briefly; the header and footer remain stationary. The animation definitions are in `src/presentation/transitions.ts`, with keyframes in `src/styles/transitions.css`.

The router uses an animation fallback when native View Transitions are unavailable and respects reduced-motion preferences. Delegated navigation handlers work after every body swap, while custom elements reconnect with lifecycle cleanup. The active theme is applied to the incoming document before swapping to avoid a light-theme flash. Language switching preserves the query and fragment before the router reads the link. External links and downloads retain their browser behavior. Without JavaScript, links load their static HTML pages normally.

## Light and dark themes

The header's sun/moon button switches between light and dark palettes. The initial theme follows the system preference unless a visitor has saved a choice. That choice is stored locally under `portfolio-theme` and persists across pages and languages. System changes are observed while no explicit choice exists; changes from other tabs are synchronized. If storage is unavailable, the choice remains available during internal navigation for the current session. A full reload returns to the system preference.

A small head script selects the saved theme before the body renders. Without JavaScript, CSS still follows the system color scheme and hides the inactive control. Semantic colors in `src/styles/global.css` use `light-dark()`; update both values when changing the palette. Action backgrounds and foregrounds are separate from link colors to preserve contrast. Diagrams use theme-aware surface and text tokens.

Theme logic lives in a pure view model, with storage access and browser event bindings in separate modules. Unit checks cover preference handling and WCAG AA contrast for principal text/surface pairs. The generated startup script is exercised in the static-output tests; browser scenarios cover both languages, keyboard activation, persistence, system changes, blocked storage, and no-JavaScript behavior.

## Quality checks

```sh
npm run validate        # Type checks, lint, formatting, unit tests, production build
npm run test:e2e        # Production browser tests; run after building
```

Browser tests require Chromium and WebKit: `npx playwright install chromium webkit`. They cover desktop/mobile navigation, internal links, the CV URL, automated accessibility checks, no-JavaScript content, and failure/recovery interaction. Configure `PLAYWRIGHT_CHANNEL=chrome` to use an installed Google Chrome for the Chromium projects. The WebKit smoke project uses its own browser binary.

ESLint requires braces for all control-flow statements, strict equality, and `const` where possible. TypeScript uses Astro's strictest preset. Prettier formats Astro and orders Tailwind utilities.

## Verification in this environment

The type, lint, formatting, unit, build, and generated-output checks run locally. Browser tests require permission to launch browsers and connect to the local preview server. External hosting, analytics account configuration, indexing, and form inbox delivery must be verified separately.

## Hosting and privacy

The project uses static HTML, locally served fonts, and build-time content. Optional Netlify Forms handles inquiries on production Netlify deploys. Optional Plausible integration measures predefined engagement events after configuration; it is disabled by default. Email and professional profile links remain available on all hosts. The CV is a downloadable public asset on any publicly deployed copy. See [deployment and activation](docs/deployment.md) for provider setup, domain configuration, privacy boundaries, and availability settings.

The tracked `.openai/hosting.json` identifies the private Sites deployment. Public access and a custom domain are separate hosting choices. Static assets can also be deployed to another provider without changing the application architecture.

## Refresh project evidence

The gateway recording is captured against a local checkout with installed dependencies:

```sh
npm run capture:gateway -- /absolute/path/to/api-gateway
npm run record:gateway
```

The first command runs the actual gateway with an isolated local upstream and asserts healthy, failing, open-circuit, and recovery responses. It writes `src/content/gateway-recording.json`, including the Git revision and checkout status. The second command renders a condensed, silent replay and poster from those responses using Playwright Chromium. Review the transcript, video, and revision before publishing. Neither command sends requests to a public service.

Study screenshots have full-size originals in `public/images/` for enlargement and matching source files in `src/assets/studies/` for responsive AVIF/WebP article images. Keep both copies synchronized when replacing evidence. Each study records its attribution and dimensions. Social PNG cards are generated at build time for every localized study and note; publication dates remain editorial inputs rather than build timestamps.
